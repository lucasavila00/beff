`validate`, `parse` and `safeParse` are faster, and the generated `parser.js` is smaller after minification.

Migration: update `@beff/cli` and `@beff/client` together, then run `beff` again to generate the parsers. A `parser.js` from an older `@beff/cli` does not work with this `@beff/client`. The new `parser.js` does not work with an older `@beff/client`.

What changes for you:

- The contents of `parser.js` are different. Do not edit this file by hand.
- `@beff/client/codegen-v2` no longer exports the runtype classes (`ObjectRuntype`, `AnyOfRuntype`, ...).
- The parsers use more memory after they load: 1.2 to 2.1 times the memory of the previous version in the benchmarks.
- A very deep recursive input overflows the stack a little earlier: at 3437 levels for `validate` (before: 3687), and at 2656 levels for `safeParse` of a valid input (before: 3000).
- `createNamedType` now accepts names such as `"constructor"` and `"toString"`. Before, it threw "Named type ... already exists" for these names.

The accepted inputs, the parsed values, the error messages and the output of `describe` and `schema` did not change.
